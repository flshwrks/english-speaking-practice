## 変更内容
- お題カード: 会話ごとに「状況・あなたの役・使える事実・ゴール」を Haiku 4.5 で生成（約6〜10秒、1枚 約0.5円）。ビジネスの場面は若手の役と数字入りの事実を渡し、学生が職歴を作り話しなくてよいように。会話 AI も同じカードを見る（カードを読み上げず、必要なときに事実を出す）
- 自分として話す場面: 外資系インターン面接・ケース面接・英語ディスカッション・研究の説明・海外で働く先輩に話を聞く。役職を聞かない決まりを会話 AI に
- 話題の重複よけ: 直近のカードの話題タグを生成時に渡し、業界・国・切り口を変える
- 再挑戦: FB から「同じお題に再挑戦」、ホームで12〜45日前のお題を提案。再挑戦の FB に「前回との比較」（話す速さ・誤りのない節・話し始めるまで・発音・流暢さ・抑揚）
- ホームを開いたときにおすすめのカードを先に作る（準備画面を待たせない）

## 理由
- 学生なのでビジネスの場面で話せる材料がなく、役職を想像で答えることになり、毎回同じ話題で成長の実感がないというフィードバック

## 検証
- カード生成の品質を3シナリオで確認。E2E でカードつき会話→同じカードで再挑戦→比較の表示まで確認し、DB はスナップショットから復元
- 型チェック・lint・単体テスト42件・本番ビルド

## 追記: カードは事前に用意したものから選ぶ方式に変更（同日）
- 理由: その場で生成すると API 費用と待ち時間がかかるため、ユーザーの要望で事前作成に
- data/cards.json に 14シナリオ × 5枚 = 70枚を用意（Claude Code 上で作成）。`npm run db:seed` で scenario_cards に入れる（slug で上書き更新）
- 選び方: まだ話していないカードを用意した順に → 全部話したら、最後に話したのが一番古いカード（自然に再挑戦になり、前回比較が出る）。「別のお題にする」は出す順で次のカードへ
- アプリ内の生成処理（Haiku 呼び出し・先行作成）と設定を削除。カードを増やしたいときは data/cards.json に追記して seed を再実行

## 追記2: カードを「シナリオ別の段階カード＋狙い＋表現」に（同日）
- 検討: 汎用カード（どのシナリオでも使える多めの情報）とシナリオ別カードを比較。汎用カードは場面と情報がかみ合わず AI の即興に頼るため不自然になり、鍛える力を設計できない。実データで今日の表現が 0/8 だったのも表現と場面が無関係だったのが一因 → シナリオ別を採用
- 70枚をすべて作り直し: 各カードに「狙い（身につける力）」と「その場面で自然に使う表現 3つ（例文つき）」を追加。シナリオ内はステップ1→5で基礎→応用に並べた（例: 進捗報告は 結論と数字 → 遅れの理由 → 挽回策と期日 → 選択肢と推奨 → リスクの先回り）
- 表現: seed でカードの表現（210個、うち11個は既存と共通）を表現リストに入れる。出題時はカードの表現を新しい枠に優先し、2〜3個は必ず出す（その分、復習枠を減らす。総数5は同じ）。カードの表現はそのカードのときだけ出る
- 会話 AI にカードの狙いを渡し、その力が必要な場面を作らせる。分析は狙いを示せたかを判定し、できていなければ要点にお手本つきで入れる
- 画面: カードに「ステップ n/5」と「狙い」、ホームの今日のレッスンにお題と狙い、カリキュラムの今週のシナリオごとに「カード n/5」と目安（各3枚）
