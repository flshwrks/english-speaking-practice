# English Speaking Practice — マスタープラン

作成日: 2026-09-26

## 1. 目的と成功基準

- **目的**: 2028年の入社までに、海外案件のビジネス会話（会議・自己紹介・報告・交渉・質疑応答）でネイティブと対等にやり取りできるスピーキング力をつける
- **利用者**: 自分専用（1ユーザー）。PC とスマホの両方で使う
- **現在地**: TOEIC 905。読み聞きは強いが、スピーキングには自信がない → 「知っているのに口から出ない」「表現が不自然」「発音・リズムが日本語寄り」が主な課題と想定
- **予算**: API 費用は月3,000円前後（約 $20）
- **FB の出し方**: 会話中は止めない。終了後にまとめてレビューする
- **成功基準（仮）**
  - 週5回・1回15〜20分の練習を続けられる（続けられることが最優先）
  - 同じ種類のミスの再発率が月ごとに下がっていく
  - 発音・韻律スコア、話速（WPM）、沈黙の長さ、語彙の多様性が時系列で改善している

## 2. 実現可能性の検討

| 要件 | 実現方法 | 判定 |
|---|---|---|
| AI とのリアルタイム音声会話 | OpenAI `gpt-realtime-mini`（WebRTC でブラウザから直接接続） | ◎ 実用レベル。応答までの遅延は1秒未満 |
| 文法・コロケーション・表現の FB | 会話ログを会話終了後に Claude（`claude-sonnet-5`）で分析し、構造化 JSON で返す | ◎ LLM が最も得意な領域 |
| 発音の指摘（音素単位） | Azure AI Speech の Pronunciation Assessment（台本なしの unscripted モード） | ○ 音素・単語ごとの正確さ、流暢さ、完全性をスコア化できる |
| イントネーション・リズムの指摘 | 同 API の **Prosody 評価**（en-US のみ）。強勢・抑揚・話速・区切りを評価し、「単調」「不自然な区切り」などの誤りも返す | ○ スコアと誤り種別まではわかる。「どう直すか」は Claude で補足説明を作る |
| 自分・苦手分野の記憶 | Postgres にプロフィール・ミス傾向・習得度を保存し、毎回プロンプトに注入 | ◎ |
| 成長の記録と自分用カリキュラム | 指標の時系列保存 ＋ Claude による週次カリキュラム生成 | ◎ |

**結論: 実現できる。** ただし次の3点を設計に組み込む必要がある。

1. **発音評価は LLM 任せにしない。** 音声 LLM は「発音がどう間違っているか」を安定して判定できないため、専用 API（Azure）を使う。
2. **文字起こしがミスを勝手に直してしまう問題への対策。** 一般的な音声認識は、話者が冠詞を落としても補った文にしがち。そうなると文法 FB が漏れる。対策として、Azure の unscripted 評価で得られる「実際に発音された語」の書き起こしを分析の正本とし、PoC でどちらが言い間違いを忠実に残すかを検証する。
3. **予算上限を仕組みで守る。** 1セッションの上限時間と月間コストメーターを実装する。

### 概算コスト（1日20分 × 月30日 = 月600分）

| 項目 | 単価の目安 | 月額の目安 |
|---|---|---|
| リアルタイム会話 `gpt-realtime-mini` | 音声入力 $10 / 出力 $20（100万トークンあたり）。プロンプトキャッシュ込みで約 $0.02〜0.05/分 | $12〜30 |
| 発音評価 Azure | 自分の発話部分だけ評価（全体の約4割 = 月4時間）。STT 基本料金＋発音評価の追加料金 | $4〜8（※要確認） |
| 会話後分析 Claude API | 1セッション数円 | $1〜3 |
| 週次レビュー（Claude Code で手動実行） | サブスクリプション内 | $0 |
| ホスティング・DB（Vercel Hobby / Neon Free）、録音は端末内保存 | 無料枠 | $0 |
| **合計** | | **約 $17〜40（2,500〜6,000円）** |

→ **月3,000円に収めるには「1日15分前後＋コスト上限ガード」が現実的なライン。** PoC で実測し、超えるようなら会話部分を Gemini Live API（Flash 系。音声入力 $3 / 出力 $12 で、`gpt-realtime-mini` より安い）に差し替える。そのため会話プロバイダは差し替え可能な設計にしておく。

## 3. アーキテクチャ

```
[ブラウザ / PWA (PC・スマホ)]
  ├─ レッスン前: 「今日の表現」3つを表示
  ├─ WebRTC ──────────────▶ OpenAI Realtime (gpt-realtime-mini)  ← 会話そのもの
  │     └ 一時トークンは自前 API から発行（API キーはサーバー側だけに置く）
  ├─ 自分の発話を VAD イベントに合わせて発話単位で切り出し（16kHz WAV）
  │     ├→ 端末の IndexedDB に保存（聞き返し用、30日で削除）
  │     └→ /api/session/[id]/utterance → Azure で発音評価（会話と並行）
  └─ 会話終了 ─▶ [Next.js API / バックグラウンド処理]      ← 毎回・自動（API）
                   1. Claude API で分析（書き起こし＋発音スコア＋プロフィール＋今日の表現）
                   2. 結果を Neon に保存 → FB 画面に表示
                   3. ミス傾向・表現の習得状態・難易度を更新

[Claude Code (手動・週1)]  /weekly-review                     ← 週次・手動（API 不要）
   Neon から1週間分を読む → 振り返り・対話 → 次週のカリキュラムと表現セットを DB に書き込む
```

- **フロントエンド**: Next.js 16（App Router）、React 19、Tailwind CSS 4、PWA 対応（スマホのホーム画面に追加できる）
- **ホスティング**: Vercel（Node.js ランタイム）。会話後の分析は Next.js の `after()` で応答後に実行し、画面は完了までポーリングする。1人用なのでキュー基盤は使わない
- **DB**: Neon Postgres の無料枠（Vercel Marketplace から接続）。無料プランでも100プロジェクトまで作れ、1プロジェクトあたり 0.5GB・月100 CU 時間。テキストとスコア中心なので、個人利用なら数年分入る。ORM は Drizzle を使う
- **録音の保存**（実装時に変更）: **端末の IndexedDB にだけ保存**し、30日で自動削除する。Azure は 16kHz の WAV を要求し、1分あたり約2MBになるため、Vercel Blob の Hobby 枠（256MB〜1GB）では足りない。聞き返しは練習直後がほとんどなので端末内で十分と判断した。スコアと書き起こしは DB に残る
- **発音評価の方式**: Azure の REST API は台本（ReferenceText）が必須なので、サーバー側で Speech SDK を使い、台本なしで評価する
- **認証**: 自分専用なので認証サービスは使わない。環境変数のパスワードと署名付き Cookie で守る（Next.js の proxy で全ページを保護する）
- **会話中の AI の振る舞い**: ビジネスシーンのロールプレイ相手として話し、会話中は訂正しない。発話が止まったら助け舟を出す。学習者プロフィール、今週の重点、「今日の表現」をシステムプロンプトに入れ、**その表現を使う場面を自然に作る**

### 主要データモデル（初期案）

| テーブル | 中身 |
|---|---|
| `learner_profile` | 自己紹介、目標、得意・苦手、興味のある業界、推定レベル（CEFR 相当） |
| `sessions` | 日時、シナリオ、時間、コスト、総合スコア |
| `utterances` | 発話ごとの書き起こし、音声ファイルのパス、Azure のスコア（音素・単語・韻律） |
| `feedback_items` | 種別（文法 / コロケーション / 語彙 / 自然さ・丁寧さ / 発音 / 韻律）、元の発話、改善例、解説、重要度 |
| `error_patterns` | ミスの型（例: 冠詞の脱落、/r/ と /l/ の混同、平板な抑揚）、出現回数、最終出現日、習得状態 |
| `expressions` | 覚える表現。出どころ（カリキュラムで与えたもの / 自分の発話の訂正から生まれたもの）、例文、使う場面、習得状態、次回の出題日（間隔反復） |
| `curriculum` | 週ごとの重点目標、シナリオ計画、その週の表現セット（週次レビューで書き込む） |
| `weekly_reviews` | 週次レビューの要約と、ユーザーのコメント |
| （`sessions.metrics`） | WPM、語彙の多様性、ミス率、発音・流暢さ・韻律スコア。日別テーブルは作らず、セッション単位で持って集計する |

## 4. 機能とカリキュラム設計

### セッションの種類
1. **ビジネスロールプレイ**（中心）: 自己紹介、定例会議での進捗報告、意見への反論、交渉、プレゼン後の質疑応答、雑談（スモールトーク）。難易度に応じて、AI の話速・語彙・割り込みの頻度・曖昧な質問の多さを変える
2. **フリートーク**: 興味のある話題で自由に話す。語彙と流暢さを診断する
3. **発音ドリル**（台本あり）: 苦手な音素や抑揚パターンを含む文を読み上げる。scripted 評価の方が精度が高いので、弱点の特定と矯正に使う
4. **復習**: 過去の FB から作った表現カードを、実際の発話で使えるか試す（「この状況で◯◯と言ってみて」）

### 全体カリキュラム（2026-09-27 追加）
12週で1周する固定のカリキュラムを `src/lib/syllabus.ts` に持ち、週が変わると自動で次へ進む（基礎 1〜4週 → 会議 5〜8週 → 応用 9〜12週。2周目以降は難易度を上げて同じ流れを回す）。週次レビューは一から計画を作らず、その週の差し替え（override）・同じ週の繰り返し（repeatWeek）・表現の追加だけを行う。

### 今日の表現（アプリからのインプット）
（2026-09-27 変更）毎回「フレーズ2つ＋単語・熟語2つ＋復習1つ」を出題する。単語・熟語は `data/vocabulary.json`（単語・句動詞・熟語・コロケーション 100件）。
訂正だけでは「知っている表現の範囲」から出られないので、毎レッスン新しい表現を与える。

- **レッスン前**: 今日の表現を3つ表示する。内訳は、新しい表現2つ（今週のテーマに沿ったもの）と、復習の表現1つ（間隔反復で出題日が来たもの）。表現ごとに、意味・使う場面・丁寧さの度合い・例文・お手本音声（TTS）を見せる
  - 例（会議テーマ）: *"Just to piggyback on what Sarah said, ..."* / *"Could you walk me through the numbers?"* / *"I'd push back a little on that."*
- **会話中**: AI がその表現を使いやすい流れを作る（例: 反論の表現なら、あえて反論しやすい提案をする）。答えを言わせるような誘導はしない
- **会話後**: Claude が、表現を使えたか・使い方が適切だったかを判定し、FB 画面に「今日の表現: 2/3 使えた」と出す
- **習得状態**: 新規 → 使おうとした → 正しく使えた → 促されずに別のレッスンでも使えた（習得）。習得まで間隔反復で繰り返し出題する
- **表現の供給源**
  1. 最初に用意する表現集（場面別に約200件: 会議、同意・反論、ぼかした言い方、確認・聞き返し、交渉、進捗報告、スモールトーク）。Phase 1 で JSON として作る
  2. 週次レビューで Claude Code が次週分を選ぶ・作る（テーマや弱点に合わせて）
  3. 会話後の FB で「ネイティブならこう言う」と示された言い換えを、ワンタップで表現リストに追加できる

### 週次レビュー（Claude Code で手動実行）
週次のカリキュラム作成は、Claude API を組み込まず、**Claude Code 上で `/weekly-review` を実行して行う**。

- **理由**
  - API 費用がかからない。予算に余裕がないので効果が大きい
  - その場でユーザーと対話できる（「今週どの場面が一番きつかった？」「来週は何に備えたい？」）。自動生成より、実際の予定（面接、留学生との交流など）に合わせたカリキュラムにできる
  - 分析の観点やプロンプトの改善を、アプリを直さずに進められる
- **手順**（プロジェクト内のスキル `.claude/skills/weekly-review/` として定義する）
  1. `npm run review:export` で、直近1週間のセッション・ミス傾向・指標・表現の習得状態を Markdown にまとめる
  2. Claude Code が読んで振り返りを書き、ユーザーと数往復やり取りする
  3. 次週の重点テーマ・シナリオ・表現セット（新規10件程度）を JSON で作る
  4. `npm run review:import` で DB に書き込む。その内容でアプリの翌週のレッスンが組まれる
- **忘れた場合の対策**: 最後のレビューから7日以上たつとアプリにバナーを出す。レビューしていない週は、前週のテーマを続けつつ、表現集と間隔反復から自動で出題する（レッスンは止まらない）
- **毎回の会話後 FB は API のまま残す**。練習直後にすぐ見られることが重要で、手動では続かないため

### 会話後の FB 画面
- 今回の要点トップ3（多すぎる指摘は定着しないため、重要度で絞る）
- 発話ごとに「あなたの発話 → ネイティブならこう言う」と、その理由（丁寧さ・場面に合っているか・自然なコロケーション）
- 発音: 単語を色分けし、タップすると自分の録音とお手本音声（TTS）を聞き比べられる。音素ごとの指摘と、日本語話者によくある原因（母音の挿入、/θ/ と /s/ の混同、強勢のない平板な発音など）の説明
- 韻律: 抑揚の単調さや区切りの位置を指摘する
- 前回との比較、繰り返しているミスの警告

### 難易度の自動調整
- 初回はレベル診断セッション（フリートーク＋短い読み上げ）で初期値を決める
- 毎回の指標（ミス率、沈黙率、WPM、Azure のスコア）から推定レベルを更新する。うまく話せていれば AI の話速を上げ、話題を抽象化し、交渉の圧を強める
- 週1回の週次レビュー（上記）で、`error_patterns` と各セッションの指標をもとに次週のカリキュラムを決める

| **2. 発音・韻律** | 発話単位の録音（端末内保存、30日で削除）、Azure 評価の非同期処理、単語の色分け、音素・韻律 FB、お手本との聞き比べ | 発音 FB が毎回出る | 2週 |

Phase 1 が終われば、それ以降は**自分で使いながら作る**。実際の使用感から優先度を見直す。

### サブエージェント / Agent Teams の採否
- **不採用（基本は単独で順番に実装）**: 各 Phase が前の Phase の成果物（DB スキーマ、録音パイプライン）に依存しており、並列化の効果が小さい。1ユーザー向けの小規模アプリで、Agent Teams の調整コストに見合わない
- **限定的に採用**: Phase 0 の検証（Realtime / Azure / コスト実測）は互いに独立しているので、サブエージェントで並行して調査できる

## 6. リスクと対策

| リスク | 対策 |
|---|---|
| 予算超過 | 1セッションの上限時間、月間コストメーター、プロバイダの差し替え（Gemini Live） |
| 文字起こしがミスを補正してしまい、文法 FB が漏れる | Phase 0 で検証し、忠実な方の書き起こしを分析の正本にする |
| 韻律評価が en-US のみ | 目標をアメリカ英語に置く（ビジネス用途では問題になりにくい） |
| iOS Safari のマイク・WebRTC の制約 | Phase 5 で実機検証。PWA では音声の自動再生に制限があるため、ユーザーの操作を起点に開始する |
| 指摘が多すぎて定着しない | FB は重要度順にトップ3＋詳細は折りたたみ。同じミスは `error_patterns` に集約する |
| API キーの漏えい | キーはサーバー側だけに置き、ブラウザには短命の一時トークンだけを渡す |
