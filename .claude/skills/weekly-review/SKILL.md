# 週次レビュー

前提: カリキュラムの骨格は `src/lib/syllabus.ts` の12週の全体カリキュラムで、週が変わると自動で次へ進む。
このレビューでは**一から計画を作らない**。1週間の結果を振り返り、必要なときだけ次を調整する。

- その週のテーマ・シナリオを差し替える（override）
- 同じ週をもう1週繰り返す（repeatWeek）
- 弱点に合わせて表現を追加する
- 難易度やプロフィールを直す

何も調整が要らない週は、振り返りの記録と表現の追加だけで終えてよい。

## 手順

### 1. データを書き出して読む
```bash
npm run review:export          # 直近7日。期間を変えるなら -- --days 14
```
出力された `reviews/<date>-export.md` を読む。今週と来週の全体カリキュラムの内容も載っている。

### 2. 振り返りを書く（日本語、簡潔に）
- 伸びた点: 指標（発音・流暢さ・抑揚・WPM・誤り率）の変化、使えるようになった表現
- 繰り返しているミスの型: 上位2〜3個。具体例を1つずつ添える
- 今日の表現の定着度: フレーズと単語・熟語それぞれの、使えた率と傾向
- 練習量と費用: セッション数、時間、月予算（既定3,000円）のペースに収まっているか

### 3. ユーザーと対話する（2〜4往復、一度に1問）
- 今週いちばん話しにくかった場面は？
- 来週、英語を使う予定はある？（あれば override でその場面に寄せる）
- 今週のテーマはもう1週続けたい？（続けるなら repeatWeek）
- 難易度（現在 N/10）は、きつい・ちょうどいい・物足りない のどれ？

### 4. 計画を JSON にする
`reviews/<date>-plan.json` に書く。**調整しない項目は省略する。**

```json
{
  "summary": "振り返りの要約（日本語, 3〜5文）",
  "userComment": "対話で聞いたユーザーの声の要約",
  "repeatWeek": false,
  "override": {
    "weekStart": "YYYY-MM-DD（差し替える週の任意の日。通常は来週）",
    "theme": "テーマ（日本語）",
    "focus": "会話 AI のプロンプトに入る重点（英語1〜2文）",
    "scenarioIds": ["negotiate"],
    "categories": ["negotiating"]
  },
  // override は weekStart 以外すべて省略可。省略した項目は全体カリキュラムのまま
  "expressions": [
    {
      "kind": "phrase | word",
      "text": "英語表現（空所は ___）",
      "meaning": "日本語の意味",
      "example": "例文",
      "scene": "使う場面（日本語）",
      "category": "meetings | agreeing_disagreeing | hedging | clarifying | negotiating | reporting | small_talk | presenting | feedback | general",
      "register": "casual | neutral | formal"
    }
  ],
  "resolvePatterns": ["直近2週間出ていない・克服したミスの型の key"],
  "level": 7,
  "profile": { "interests": "更新があれば" }
}
```

判断の目安:
- **repeatWeek**: 今週の今日の表現の使用率が低い、またはユーザーが続けたいと言ったとき。進行が1週遅れる（`profile.week_offset` が1増える）。同じ JSON を2回取り込むと2週遅れるので注意
- **override**: 実際の予定（面接・発表・交流会など）に合わせたいとき、または弱点が全体カリキュラムの次の週とずれているときだけ
- **expressions**: 取り込んだ週のレッスンで優先して出題される。繰り返しているミスの「正しい言い方」や、来週のテーマで不足している表現を、フレーズと単語・熟語を合わせて5〜10件。出題待ち（queued）が十分にあるカテゴリには足さない。ネイティブがビジネスで本当に使う、汎用性の高いものを選ぶ
- **level**: ユーザーの体感と指標が一致して変えるべきときだけ

### 5. 取り込む
```bash
npm run review:import -- reviews/<date>-plan.json
```
成功したら、来週の内容（全体カリキュラムの週、調整の有無）と追加した表現数をユーザーに伝えて終わる。
