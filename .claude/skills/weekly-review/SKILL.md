# 週次レビュー

前提: カリキュラムの骨格は `src/lib/syllabus.ts` の12週の全体カリキュラムで、週が変わると自動で次へ進む。
このレビューでは**一から計画を作らない**。1週間の結果を振り返り、必要なときだけ次を調整する。

- その週のテーマ・シナリオを差し替える（override）
- 同じ週をもう1週繰り返す（repeatWeek）
- 弱点に合わせて表現を追加する
- 難易度やプロフィールを直す

何も調整が要らない週は、振り返りの記録と表現の追加だけで終えてよい。

## 手順

### 1. データを書き出して読む
```bash
npm run review:export          # 直近7日。期間を変えるなら -- --days 14
```
出力された `reviews/<date>-export.md` を読む。今週と来週の全体カリキュラムの内容も載っている。

### 2. 振り返りを書く（日本語、簡潔に）
- 伸びた点: 指標（発音・流暢さ・抑揚・WPM・誤り率）の変化、使えるようになった表現、improving / resolved になったミスの型
- 繰り返しているミスの型: 「ミスの型」の優先度の上位2〜3個（active と reopened）。具体例を1つずつ添える。
  reopened（克服後に再発）は特に取り上げる
- 今日の表現の定着度: 新規・復習それぞれの使えた率と傾向
- 間隔反復の健全性（下の目安で読む）
- 練習量と費用: セッション数、時間、月予算（既定3,000円）のペースに収まっているか

データの読み方（計算は `src/lib/srs.ts` / `weakness.ts` / `adaptivity.ts`）:
- **ミスの型**: 固定カタログ（`src/lib/error-patterns.ts`）の key で数える。優先度は最近・重いミスほど高い（2週間で約1/3に減衰）。
  3セッション続けて出なければ improving、6セッションで自動的に resolved になる（手で克服済みにする必要はほぼない）
- **期限の件数**: 今日が期限の表現が多いほど、1回の出題は復習が増えて新規が減る（期限12件以上で新規0）。
  期限が1週間以上多いままなら、表現を足すより練習回数か使用率の問題
- **一度も使えていない表現・苦手（leech）**: 3回続けて使わなかった表現は2週間休ませ、そのあと優先度を上げて復習に戻る。
  苦手が5件を超えたら、表現が場面に合っていない・難しすぎる可能性が高い
- **難易度**: 会話ごとに自動で調整される（1回では動かず、2回続けて余裕・苦戦のときだけ ±1）

### 3. ユーザーと対話する（2〜4往復、一度に1問）
- 今週いちばん話しにくかった場面は？
- 来週、英語を使う予定はある？（あれば override でその場面に寄せる）
- 今週のテーマはもう1週続けたい？（続けるなら repeatWeek）
- 難易度（現在 N/10）は、きつい・ちょうどいい・物足りない のどれ？

### 4. 計画を JSON にする
`reviews/<date>-plan.json` に書く。**調整しない項目は省略する。**

```json
{
  "summary": "振り返りの要約（日本語, 3〜5文）",
  "userComment": "対話で聞いたユーザーの声の要約",
  "repeatWeek": false,
  "override": {
    "weekStart": "YYYY-MM-DD（差し替える週の任意の日。通常は来週）",
    "theme": "テーマ（日本語）",
    "focus": "会話 AI のプロンプトに入る重点（英語1〜2文）",
    "scenarioIds": ["negotiate"],
    "categories": ["negotiating"]
  },
  // override は weekStart 以外すべて省略可。省略した項目は全体カリキュラムのまま
  "expressions": [
    {
      "kind": "phrase | word",
      "text": "英語表現（空所は ___）",
      "meaning": "日本語の意味",
      "example": "例文",
      "scene": "使う場面（日本語）",
      "category": "meetings | agreeing_disagreeing | hedging | clarifying | negotiating | reporting | small_talk | presenting | feedback | general",
      "register": "casual | neutral | formal"
    }
  ],
  "resolvePatterns": ["（通常は省略）ユーザーが克服を確認した improving の型の key"],
  "level": 7,
  "profile": { "interests": "更新があれば" }
}
```

判断の目安:
- **repeatWeek**: 今週の新規の表現の使用率が3割未満、またはユーザーが続けたいと言ったとき。進行が1週遅れる（`profile.week_offset` が1増える）。同じ JSON を2回取り込むと2週遅れるので注意
- **override**: 実際の予定（面接・発表・交流会など）に合わせたいとき、または弱点が全体カリキュラムの次の週とずれているときだけ
- **expressions**: 取り込んだ週のレッスンで優先して出題される。繰り返しているミスの「正しい言い方」や、来週のテーマで不足している表現を、フレーズと単語・熟語を合わせて5〜10件。出題待ち（queued）が十分にあるカテゴリには足さない。ネイティブがビジネスで本当に使う、汎用性の高いものを選ぶ。
  今日が期限の表現が8件以上あるときは、新規はほとんど出題されないので3件以内に絞る
- **resolvePatterns**: 自動で resolved になるので通常は不要。improving の型をユーザーが「もう大丈夫」と確認したときだけ入れる。再発すれば自動で戻る
- **level**: 自動調整があるので、ユーザーの体感と指標がはっきりずれているときだけ

### 5. 取り込む
```bash
npm run review:import -- reviews/<date>-plan.json
```
1つのトランザクションで書き込む。同じ summary の計画は2回取り込めない（取り込み済みとエラーになる）。
直して取り込み直したいときは summary を変える。
成功したら、来週の内容（全体カリキュラムの週、調整の有無）と追加した表現数をユーザーに伝えて終わる。
